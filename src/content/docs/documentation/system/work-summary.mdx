**Work Summary** is a manager-facing dashboard covering every evaluator over a chosen date range, not a personal self-report. It's a separate feature from [Piecework / Payment Process](/docs/procedures/piecework), that page determines pay, this one is for spotting patterns in appointment load, lateness, and reporting.

## Picking a range

A range toggle (**4 Weeks**, **3 Months**, **6 Months**, or **Custom** with its own from/to date pickers) sets the window, and a separate **Display** toggle (**Total**, **Avg / Wk**, **Median / Wk**) controls how the appointment counts below are aggregated, a running sum for the whole range, or a per-week average or median.

## The four cards

- **Appointments by Evaluator**: counts per evaluator, broken out by DA/EVAL/DAEVAL, and for EVAL/DAEVAL further split by diagnosis (ASD, ADHD, ASD+LD, ADHD+LD, LD) and age band. Clicking a row opens the Database page's Appointments table for the same dates, filtered to that evaluator. It shows the date, client, type, and projected versus logged minutes for each appointment.
- **Appointment Timing**: one row per evaluator with three groups, each showing an average and a median. **Appointment length vs expected** reads like "5 min over" or "3 min under". **Late start** compares when the appointment started to its scheduled time (or to when the client arrived, if later). **Arrival** compares the evaluator's day check-in to their first scheduled appointment. Late start and arrival read like "5 min late" or "3 min early". A dash means there is no data yet. Times come from [Arrivals and Departures](/docs/documentation/scheduling/arrivals-and-departures).
- **Reports Written**: a count per writer, sourced from the same report-tracking data [Piecework](/docs/procedures/piecework) uses to figure out who gets credit for a report.
- **Appointment Check-ins**: one row per person who checked someone in. **Client check-ins** counts how many clients they marked as Arrived, Started, and Left. **Evaluator check-ins** counts how many evaluator day check-ins they marked as Arrived and Left. An **Out of order** column appears only when someone entered a time earlier than the step before it (for example a left time before the started time), and counts those entries per person. Click a client count or an Out of order count to open the Database page's Appointments table for the same dates, filtered to that person.

## Where "expected duration" comes from

Projected/expected minutes are looked up per evaluator first (their own configured durations, if set), falling back to a site-wide default. Those defaults live at **Settings > Practice > Appointment Durations**: a grid of hour values (half-hour steps) for DA, and for EVAL/DAEVAL split by age band and diagnosis. Editing the defaults requires the **Manage Evaluators** permission, and they only apply when an individual evaluator has nothing more specific configured for that same combination.

## Edge cases

- **Projected Hours and Logged Hours columns only appear when there's actually duration data to show.** Their absence for an evaluator or range isn't a bug, it just means nothing to compute from yet.
- **The default durations are a fallback, not an override.** An evaluator with their own duration set for a given appointment type/age/diagnosis combination won't be affected by changing the site-wide default for that same combination.
