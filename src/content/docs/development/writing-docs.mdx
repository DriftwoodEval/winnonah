Docs are plain Markdown/MDX files in `src/content/docs/`, organized into category folders.

## Frontmatter

```md
---
title: My Page Title
needsCleanup: true
notDone: false
---
```

- `title` (required) — shown in the sidebar, browser tab, and rendered as the page's heading. Must be unique within its category.
- `needsCleanup` (optional boolean) — renders a "this page is still rough" banner at the top, for a page that's accurate but too technical or missing screenshots.
- `notDone` (optional boolean) — renders a "work in progress" banner, for a page that isn't finished being written.

Pages within a category are sorted alphabetically by title, so there's no `position` to set.

## Categories

Each top-level folder under `src/content/docs/` is a sidebar category. Add a `_category.json` next to the docs in that folder to control its label and order:

```json
{
	"title": "Development",
	"position": 99,
	"standalone": false
}
```

- `title` — the sidebar heading for the category. Without a `_category.json`, the folder name is title-cased automatically.
- `position` — lower numbers sort higher in the sidebar. Categories without one sort last.
- `standalone` (optional boolean) — the category's pages render as a flat list with no heading, and consecutive standalone categories merge into one block. Also hides the category from the "new doc page" folder picker.

## Callouts

Use callouts to pull something out of the main flow: a warning, a tip, a "this only applies if" note. Lean on them, a page with two or three well-placed callouts is easier to scan than one long wall of text.

Write them as a blockquote with a marker on the first line:

```md
> [!NOTE]
> Background or context the reader should have.

> [!WARNING]
> An action that can cause problems or lost work.
```

Everything below the marker line is the callout body and can hold normal Markdown (links, bold, lists).

The body is optional. A marker on its own renders just the type heading, and a marker with text after it renders that text as the heading with nothing below:

```md
> [!WARNING] Do not skip this step
```

> [!WARNING] Do not skip this step

> [!TIP]
> The marker is case-insensitive. To override the heading, put text after it on the same line: `> [!WARNING] Read this first`. That heading text can use inline formatting (emphasis, `code`, links).

Add a `~` right after the marker to render the heading in normal weight instead of bold:

```md
> [!NOTE]~ A quieter heading
> body text
```

> [!NOTE]~ A quieter heading
> body text

### Types

The types available are `note`, `abstract`, `info`, `todo`, `tip`, `success`, `question`, `warning`, `important`, `caution`, `failure`, `danger`, `bug`, `example`, `quote`. An unrecognized marker falls back to `note`.

There are some aliases that resolve to another type: `summary`/`tldr` to abstract, `hint` to tip, `check`/`done` to success, `help`/`faq` to question, `attention` to warning, `fail`/`missing` to failure, `error` to danger, `cite` to quote.

## Screenshots and other images

Put image files right next to the `.mdx` file that uses them, then reference them by filename:

```md
![Description of the screenshot](cheddar.jpg)
```

For this file, that means the image lives at
`src/content/docs/development/cheddar.jpg`. A build step rewrites relative
paths like that into the `/docs/images/...` route that actually serves them,
so you don't need to spell out the full path yourself.
